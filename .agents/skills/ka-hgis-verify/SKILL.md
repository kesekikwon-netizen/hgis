# ka-hgis 확인 루프

Cursor 프로젝트 스킬이다. Claude Code 전용이 아니다. 코드 확인(Graft, clangd, Archify, ctest)은 `AGENTS.md`가 맡고, 이 스킬은 **사용자가 앱에서 보는 결과**를 맡는다.

테스트가 통과해도 화면 동작이 끝났다고 하지 않는다. 계정, 쿠키, 비밀번호는 스킬·로그 인용·화면 설명에 넣지 않는다. 실행 중인 앱은 끄거나 다시 열지 않는다.

## 루프

1. 사용자가 볼 동작 하나를 고른다.
2. 통과 조건을 측정값으로 적는다. 「됐을 것」은 조건이 아니다.
3. 그 측정을 실행한다. 실패하면 고치고 같은 측정을 다시 실행한다.
4. 답에는 입력과 결과를 적는다. 도구 이름만 적지 않는다.

| 보는 것 | 측정 |
|---|---|
| 빌드가 아이콘과 연결됨 | 바탕화면 바로가기가 이 폴더 `launch.ps1`을 실행하고, 그 스크립트가 `build/Release/ka-hgis.exe`를 연다 |
| 앱이 뜨는지 | 앱이 꺼져 있을 때만 `.\scripts\run-ka-hgis.ps1 --smoke-quit`. 종료 코드 0 |
| 리본·창 크기 | 해당 `ctest`와, 사용자가 준 캡처에서 겹침·잘림 |
| 주변유적 받기 | 아래 기록. 실서버에 새 받기를 걸지 않는다 |

## 주변유적 받기

인트라넷 절차는 [문화재인트라넷](../heritage-intranet/SKILL.md)을 따른다. 여기에는 성공 판정만 둔다.

기록 파일은 `%LOCALAPPDATA%\ka-hgis\ka-hgis\주변유적\<시도 시군>\receipts\` 아래 진단 텍스트다. 로그인 줄은 읽지 않는다.

통과는 같은 시도에서 이 순서가 있을 때뿐이다.

1. `공식 전체다운로드 버튼 1회 실행`
2. `파일 수신 시작`
3. `받음:` 경로와 0보다 큰 바이트

이것만으로는 통과가 아니다.

- `공식 전체다운로드 요청 전송 확인` 또는 `파일 응답 대기`
- 화면의 `서버가 파일을 만드는 중`, 경과 초, `보통 40~120초`
- 인트라넷 화면 가운데 스피너
- 창을 닫다 난 크래시

오늘 같은 경주 지정유산은 요청 후 약 4초에 `파일 수신 시작`이 찍힌 적이 있다. 그 줄이 없는데 1분이 넘으면 서버가 파일을 아직 주지 않은 것이다. 취소를 성공으로 적지 않는다. 여섯 자료는 한 종류가 `받음` 된 뒤에만 다음으로 간다.
