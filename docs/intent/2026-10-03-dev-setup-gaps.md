## 문제
- 작업 지침(CLAUDE.md)이 약 2만 자다. Anthropic 공식 안내는 "짧게 유지하라, 길면 절반을 무시한다"고 한다. 다른 대화에서 스킬·단계가 빠진 원인 가운데 하나로 본다(추측).
- Claude가 시험이 안 맞을 때 원래 있던 시험의 기댓값을 바꾸거나 시험을 지워 "통과"로 만들어도 막는 장치가 없다.
- C++ 코드를 정확히 찾아 주고 고친 직후 오류를 알려 주는 도구(clangd-lsp)가 꺼져 있다. clangd 22.1.8은 이 PC에 있지만, 작업 폴더 빌드에는 그 도구가 읽는 빌드 정보 파일(compile_commands.json)이 없다.

## 바라는 결과
- 작업 지침이 절반 이하로 줄고, 매번 꼭 필요한 규칙만 남는다. 가끔 필요한 내용은 필요할 때만 읽는 참고 문서로 옮겨 사라지지 않는다.
- 원래 있던 시험의 기댓값을 바꾸거나 지우는 커밋은 한 번 멈춘다. 이유를 적어야 통과하고, 보고에 「바꾼 시험」이 반드시 보인다.
- 새 대화에서 Claude가 C++ 코드의 정의·사용처를 정확히 찾고, 고친 직후 컴파일 오류를 바로 본다.

## 영향받는 곳
- CLAUDE.md, 새 참고 문서(docs/agent/ 아래), 커밋 전 검사 장치(.claude/hooks), 전역 설정의 추가 기능 목록, 빌드 설정(빌드 정보 파일 만들기)
- 앱 기능·화면·조사 자료는 바뀌지 않는다.

## 지켜야 할 것
- 사용자가 정한 규칙(제품 규칙, 필드 동작, 키·좌표계·충돌 규칙, Jev는 개발에만, 스킬 적극 사용 등)은 뜻을 하나도 빼지 않는다. 줄이는 것은 설명·중복·예전 경위다.
- 지금 장치(단계 알림, 마무리 직전 확인, 자동 백업, 커밋 전 검사)는 그대로 둔다.
- 새 프로그램 설치나 유료 도구는 쓰지 않는다. clangd는 이미 설치된 것을 쓴다.
- 기술 선택(Claude가 정함): 검사 잠그기는 커밋 전 검사 장치에 붙이고 시험을 단다. 이유는 커밋 메시지의 「시험 변경:」 줄로 받는다. 빌드 정보 파일은 CMake 설정으로 만든다.

## 확인 방법
- 새 대화에서 Claude가 처음에 읽는 작업 지침이 절반 이하로 줄었다(보고에 전후 글자 수).
- 시험 기댓값을 바꾼 커밋을 시험 삼아 해 보면 「시험 변경」 이유를 요구하며 한 번 막힌다.
- 새 대화에서 Claude에게 C++ 함수 하나의 사용처를 찾게 하면 코드 도구로 찾는다.

## 결과
- 작업 지침: 16,902자 → 8,856자(52%). 처음에 8,448자(50%)까지 줄였으나, 코드 검토에서 빠진 뜻 6가지(키 읽는 순서, 시험 못 붙이는 화면 코드는 지우지 않기, 저장 안 된 앱은 닫지 않기 등)가 나와 되살렸다. 절반을 조금 넘는 대신 뜻을 지켰다. 옮긴 내용은 docs/agent/strata-reference.md. 낡아서 뺀 것: 「커밋」 때만 main에 넣기(10-03부터 커밋마다 올림), claude/strata-merge-20261001이 main에 없다는 메모(이미 합쳐짐).
- 검사 잠그기: 커밋 전 검사 장치가 원래 있던 시험의 검사문·데이터 줄·등록 이름이 사라지거나 바뀌거나, 건너뛰기가 생기면 `시험 변경:` 이유 줄 없이는 막는다(여러 줄 검사문, 이름 바꾼 시험 파일, 여러 줄 등록 목록 포함, 새 시험의 조건부 건너뛰기는 통과). 장치 시험 15개 통과(바꾸기 전 실패 확인). 최근 커밋 97개에 적용하면 40개가 이유 줄을 요구했고 모두 실제로 기존 시험을 바꾼 커밋이었다.
- C++ 코드 도구: Visual Studio 빌드는 빌드 정보 파일을 만들지 않아(작은 시험으로 확인) CMake 빌드 정보에서 만드는 변환기(scripts/compile-commands.mjs, 시험 4개)를 빌드에 연결했다. PC에 함께 있는 Visual Studio 18판 헤더를 잡아 생기던 가짜 오류(LayerOps.cpp 13건)를 빌드용 MSVC 지정으로 0건으로 만들었다(실제 파일 4개 0건). clangd-lsp 추가 기능을 켰고(설정 백업 _reset_backup/20261003-0109-clangd-lsp), 새 대화(2.1.288)에서 LSP 도구로 선언·참조를 찾는 것을 확인했다. 파일 전체 색인은 첫 대화에서 쌓이기 시작한다(build/.cache, 54개). 예전 생성 스크립트(gen-compile-commands.ps1, compiledb 프리셋)는 이 변경으로 필요 없어져 지웠다.
