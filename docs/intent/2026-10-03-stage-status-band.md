# 요청 기록: 입력칸 위 한 줄에 지금 단계와 마지막 빌드·시험 결과 보이기

- 날짜: 2026-10-03
- 상태: 확정
- 관련 문서: 없음

## 요청 원문
> https://claude.dev/blog/getting-started-with-claude-code-mods/
> 추천진행

(직전 제안 1번: 「입력칸 위 한 줄: 지금 단계 + 마지막 빌드·시험 결과 (예: 「시험 먼저 · 빌드 ✓ · 시험 12/12」)」을 추천한 데 대한 답)

## 문제
- Claude가 지금 어느 단계(원인 찾기, 시험 먼저, 끝나기 전 확인 …)에 있는지, 마지막 빌드·시험이 통과했는지는 긴 대화를 거슬러 읽어야 알 수 있다.
- 사용자는 개발자가 아니라 명령 출력에서 결과를 찾기 어렵다(추측).

## 바라는 결과
- Claude Code 입력칸 바로 위에 한 줄이 늘 보인다: 「지금 단계 · 빌드 결과 · 시험 결과」.
- Claude가 단계 스킬을 부르면 단계 이름이 한국어로 바뀌고, 빌드·시험을 돌리면 결과가 바로 바뀐다.

## 영향받는 곳
- Claude Code 화면(데스크톱 앱 Code 탭, 터미널)의 입력칸 위 한 줄
- Strata 앱 화면·기능·조사 자료: 바뀌지 않는다

## 지켜야 할 것
- 보여 주기만 한다. Claude의 명령을 막거나 바꾸지 않는다(막는 일은 커밋 전 검사가 이미 한다).
- 남이 만든 mod는 설치하지 않는다. 저장소 안에서 직접 만든다.
- 키·조사 자료를 읽거나 밖으로 보내지 않는다. 인터넷을 쓰지 않는다.
- 기술 선택(Claude가 정함): 저장소 안 플러그인 mod로 만들고, Skill 도구 호출과 빌드(`cmake --build`)·시험(`ctest`) 명령의 결과를 지켜봐서 한 줄을 그린다.

## 이번에 하지 않는 것
- 대화 길이 표시, 앱 켜짐 알림, 위험 명령 미리보기(제안 2~4번)
- Strata 앱 자체 변경

## 미정 질문
1. 어느 대화에서 보일까요? — 추천: Strata(A:\qgis) 대화에서만 — 사용자 답: 추천대로
2. 무엇을 보일까요? — 추천: 단계 · 빌드 ✓/✗ · 시험 통과 수/전체(실패면 ✗와 실패 수). 아직 안 돌렸으면 「—」 — 사용자 답: 추천대로
3. 데스크톱 앱과 터미널 둘 다? — 추천: 둘 다 — 사용자 답: 추천대로

## 확인 방법
- 이 창 입력칸 바로 위에 「단계 · 빌드 · 시험」 한 줄이 보인다.
- Claude가 시험을 돌리고 나면 그 줄의 시험 숫자가 바뀐다.

## 결과
- 2026-10-03: mod를 `scripts/claude-mods/strata-status-band/`에 만들었다. `claude plugin test` 16개 통과, `claude plugin validate` 통과(경고: 작성자 정보 없음).
- 아직 화면에서 보지 못했다: 이 대화의 hot reload는 사용자가 「Not now」를 골랐고, 앞으로의 대화에 싣는 전역 설정(`~/.claude/settings.json` env `CLAUDE_CODE_PLUGIN_DIRS`) 변경은 자동 모드가 막아 사용자 결정을 기다린다.
- 남긴 것(검토 지적 중 고치지 않음): 명령 글에 `cmake --build`·`ctest`가 들어 있기만 해도(예: 그 글자를 grep) 결과로 읽는다. `| tail`로 종료 코드가 사라진 빌드는 ✓로 보일 수 있다.
