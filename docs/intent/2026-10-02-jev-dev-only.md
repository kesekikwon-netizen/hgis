# 요청 기록: Jev를 앱이 아니라 개발 작업에만 쓰기

- 날짜: 2026-10-02
- 상태: 확정
- 관련 문서: docs/intent/2026-10-02-jev-in-app.md (취소), Strata 작업 지침(CLAUDE.md)의 Jev 줄, scripts/jev/jev-ask.mjs (개발 도우미)

## 요청 원문
> 지금 jev를 이용하는게 규칙에없나?
> jev규칙적용
> 지금 jev규칙 mcp skills를 모두 이용해 개발진행
> jev는 앱적용이 아니라 개발에만 적용해야한다 기록 기억
> [가림] (TypeSafe API 키를 채팅에 붙여 주심)
> 나머지개발을 진행하자

## 문제
- 오늘 낮 다른 대화가 Jev를 앱 검색창 지번 찾기에 넣기로 기록하고(2026-10-02-jev-in-app), 작업 지침에 「앱 안에서 쓴다」는 규칙 줄을 넣었다. 사용자 뜻은 앱이 아니라 개발 작업에 쓰는 것이다.
- 지금 개발 중 판정(코드 검토에서 찾은 문제가 진짜인지, 원인 찾기의 가설 중 무엇이 맞는지)은 Claude 검토자 여럿이 말로 찬반을 낸다. Jev는 이런 판정을 예/아니요·고르기·점수와 확률로 돌려준다(TypeSafe 문서).
- 이 PC에는 Jev 키가 설정돼 있지 않고(환경 변수 TYPESAFE_API_KEY 없음), TypeSafe 플러그인은 설치만 되고 꺼져 있다. 그래서 지금은 개발에서도 Jev를 쓸 수 없다.

## 바라는 결과
- 개발 단계에서 판정이 필요한 곳에 Jev를 쓰고, 그 판정과 확률을 보고에 한 줄로 보인다.
- 앱(Strata)에는 Jev 코드·키·인터넷 호출이 들어가지 않는다.
- 작업 지침과 Claude 기억이 이 결정을 따른다.

## 영향받는 곳
- 개발 과정: 코드 검토, 원인 찾기, 설계 비교(추천안 기준)
- Strata 작업 지침의 Jev 줄, Claude 기억(jev-typesafe)
- 앱 화면·기능: 바뀌지 않는다

## 지켜야 할 것
- 키는 저장소·코드·보고에 쓰지 않는다. 키 설정은 사용자가 직접 한다(Claude는 키를 입력하지 않는다).
- Jev로 보내는 것은 코드 조각·시험 결과·검토 문장뿐이다. 조사 자료(GPKG·좌표·의뢰처 도면 원본)와 키·비밀번호는 보내지 않는다(미국 서버로 간다).
- Jev 판정만으로 코드를 고치거나 문제를 버리지 않는다. 마지막 결정은 지금처럼 빌드·시험으로 확인한다.
- 키가 없거나 인터넷·크레딧이 없으면 지금 방식(Claude 검토자)으로 그대로 개발하고 보고에 한 줄 적는다.
- 방법은 Claude가 정한다: TypeSafe 공식 API를 개발 도구에서 직접 부르고, 남이 만든 Jev 플러그인은 깔지 않는다(추측: 공식 문서만으로 충분).

## 이번에 하지 않는 것
- 앱 검색창 지번 찾기에 Jev 넣기(2026-10-02-jev-in-app, 취소)
- 앱의 다른 곳(유적 검색, 측량 점 파일, 유구 종류 등)에 Jev 넣기

## 미정 질문
1. 개발의 어느 단계에 Jev를 쓸까요? — 추천: 코드 검토에서 찾은 문제가 진짜인지 판정하기와 원인 찾기의 가설 순위 매기기. 설계 비교는 그다음. — 사용자 답: 키를 보내고 「나머지개발을 진행하자」 — 추천대로
2. Jev 판정과 Claude 검토자 판정이 다르면? — 추천: 둘 다 보고에 적고 시험으로 가린다. 어느 한쪽만 믿지 않는다. — 사용자 답: 추천대로
3. 보고에 어떻게 보일까요? — 추천: 단계마다 「Jev 판정 n건 · 진짜로 본 것 m건 · 비용 약 $0.0x」 한 줄. — 사용자 답: 추천대로

## 확인 방법

- 키를 설정한 뒤 다음 코드 검토 보고에 Jev 판정 줄이 나온다.
- 앱 소스에 TypeSafe 호출이 없다.
