# 요청 기록: 최고의 개발환경 만들기

- 날짜: 2026-10-02
- 상태: 확정
- 관련 문서: 없음

## 요청 원문
> 최고의 개발환경을 만들라
> (같은 날 저장소를 새 GitHub로 옮기고 올린 뒤, 같은 말로 다시 요청)
> 추천대로 진행

## 문제
- 매 메시지마다 붙는 자동 알림이 옛 규칙(슈퍼파워를 무조건 쓰고, 과제마다 하위 에이전트를 돌린다)을 계속 넣는다. 오늘 정한 「빠르게 진행」 방식과 어긋난다. 설치된 알림 장치가 main의 것보다 오래되었다.
- 새 대화는 새 작업 폴더에서 시작한다. 그래서 앱을 처음 빌드하는 데 약 8분이 걸린다. 화면에서 확인할 때마다 그만큼 기다린다.
- 새 GitHub의 자동 검사는 마지막으로 끝난 실행이 실패였다. 지금 2개가 돌고 있어서 통과할지는 아직 모른다.
- 원래부터 실패하는 시험 4개가 늘 남아 있다. 그래서 새로 깨진 시험과 구분하기 어렵다.
- 정리하지 않은 것이 남아 있다. 시험용 폴더 `A:\tmp-setup-test`, 컴파일러 프로그램 5개(다른 대화의 빌드일 수도 있음, 추측), 쓰지 않는 작업 폴더가 있다. 다른 작업 폴더(happy-davinci)에는 저장하지 않은 변경 11개가 있다.

## 바라는 결과
- Claude가 오늘 정한 방식(가볍게 진행, 확인은 한 번)으로만 움직이고, 서로 다른 규칙이 섞이지 않는다.
- 새 대화에서도 앱을 몇 분 안에 빌드해 확인할 수 있다. 목표 시간은 재 본 뒤 정한다.
- GitHub 자동 검사가 끝까지 돌고 통과(초록)로 끝난다.
- 시험이 전부 통과 상태가 되어, 새로 깨진 것이 바로 보인다.
- 작업이 한 곳(PC main = GitHub main)에 모이고, 남은 찌꺼기가 정리된다.

## 영향받는 곳
- 전역 설정(매 메시지 알림), Strata 빌드 설정, GitHub 자동 검사 설정, 실패하던 시험 4개(시험 또는 앱 코드), 작업 폴더들, Claude 기억 메모

## 지켜야 할 것
- 앱의 화면과 동작은 바꾸지 않는다. 현장 규칙과 제품 규칙은 그대로 둔다.
- 저장하지 않은 작업이 있는 작업 폴더는 지우지 않는다. 무엇이든 지우기 전에 목록을 보여 준다.
- 사용량을 아낀다(가벼운 방식). 결제·계정 설정은 사용자가 한다.
- 기술 선택: 빌드 시간은 새 프로그램을 설치하지 않는 방법부터 재 보고 줄인다(Claude가 정함).

## 이번에 하지 않는 것
- 앱 화면·기능 바꾸기, 새 플러그인 묶음 추가, 다른 프로젝트(A:\hgis 등) 개별 설정

## 미정 질문
1. 원래 실패하던 시험 4개를 이번에 고쳐서 전부 통과로 만들까요? — 추천: 예. 고치면서 앱 동작이 바뀌어야 하면 먼저 알린다. — 사용자 답: 「추천대로」— 예
2. 빌드 시간을 줄이는 데 새 프로그램 설치가 필요하면 허락하시겠어요? — 추천: 아니요. 설치 없이 되는 방법으로 먼저 줄이고 결과를 보여 드린 뒤 다시 묻는다. — 사용자 답: 「추천대로」— 아니요, 설치 없이 먼저
3. 다른 대화(happy-davinci)의 저장 안 된 변경 11개는 어떻게 할까요? — 추천: 건드리지 않고, 무엇인지 목록만 보여 드린다. 그 대화가 아직 진행 중일 수 있다. — 사용자 답: 「추천대로」— 건드리지 않고 목록만

## 확인 방법
- GitHub 저장소의 Actions 탭에서 가장 최근 실행이 초록색 체크로 끝난다.
- 보고에 「새 작업 폴더 첫 빌드: N분」이 적히고, 8분보다 짧다.
- 보고에 「시험 전부 통과」가 적힌다.
