디자인 시스템(p01)은 다음 넷으로 고정한다. 모든 패키지가 같은 값을 쓴다.

- **4 px 격자**: 4·8·12·16·24·32만. 페이지 여백 20, 카드 안쪽 16, 카드 사이 16, 홈 표 행 48, 레이어 목록 행 18(유지), 칩 높이 22(r 11), 지도 위 단추 36×36, 입력 칸 30~32.
- **아이콘**: 단색 외곽선(`iconPalette().ink`), 타일 없음. 켜짐(checked)만 `accentWash` 둥근 타일 + `accent` 글리프. 미저장 「저장」만 `accent` 타일 + 흰 글리프 + `warn` 점.
- **상태 칩 한 가지 모양**: `KaChip::paintChip` 하나. 톤(ok/warn/danger/accent/neutral)만 다르다. 칩은 항상 **글리프 + 글자**(색만으로 말하지 않음).
- **빈 상태·오류·진행은 문장으로**: 표·패널이 비면 한 문장, 오류는 what/why/how(`KaUserError`), 진행은 「…하는 중입니다」.

## 3. 구현 패키지 (A) — 6개, 파일 겹침 없음

공유 파일 규칙: `data/theme/ka-hgis.qss`, `src/app/MainWindow.h`, `CMakeLists.txt`는 **추가만**. QSS는 파일 끝에 `/* ---- [P#] … ---- */` 블록을 덧붙이고 기존 선택자를 재정의하지 않는다. `MainWindow.h`는 전방 선언·멤버·메서드 선언을 끝에 덧붙이며 P6만 실제로 쓴다. `CMakeLists.txt`는 (a) 새 `.cpp`를 기존 타깃 소스 목록 **끝에 한 줄 추가**, (b) 새 시험 타깃 블록을 끝에 덧붙이기만. 그 밖의 파일은 한 패키지만 만진다.

**의존과 순서**: P1 → P2 → {P3, P4, P5 병렬} → P6. P3·P4·P5는 P1의 `KaChip`·`warn` 토큰·`contrastRatio`와 P2의 새 글리프 id를 쓴다(`tests/test_icons.cpp:39-56`이 `src/app/*.cpp`에서 id를 스캔하므로 P2가 먼저 들어가야 `everyUsedIdHasItsOwnGlyph`가 초록). 병렬 워크트리는 P1+P2 병합 지점에서 딴다.

## 7. 결정 필요 (E) — 사용자에게 물을 것만

1. **레이어 목록 행 높이**: 10 px 글자는 유지한다. 구역 띠 16 px만 더한다. 행을 18→22 px로 올릴지(장갑 타깃)는 이 문서가 **표시만** 한다. 기본안: 18 유지.

4. **사진 탭**: 문장만 있는 탭(기본안, 목업과 같은 3탭) / 탭 자체 숨김.
5. **IBM Plex 켜는 시점과 `data/fonts` 커밋**: 파일·고지(`THIRD_PARTY_NOTICES.md:28-35`)는 이미 워크트리에 있지만 미추적. P1은 연결 지점과 `bundledFonts=false`까지. 켜면 `test_theme.cpp` 픽셀 검사와 리본 라벨 폭(`applyTwoLine` 52 px), 좌표 읽기 모노를 다시 재야 한다. 기본안: 커밋 여부 사용자 결정, 옵션은 꺼 둠.

7. **「자석」 상태줄 칩 클릭**: 표시 전용(기본안) / 누르면 `applySnapSettings`+`applySnapConfig()`로 켜고 끄기(새 동작 경로 하나).

9. **상태줄 `toolChip` 유지**: 띠가 같은 정보를 보여 준다. 기본안: 유지(도면·단면도 탭에서도 보임).
